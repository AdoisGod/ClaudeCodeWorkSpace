# Technical Presentation Guide

## 簡報類型選擇

```
目標是什麼？

爭取預算/核准  → Equipment Proposal（10-15 頁）
分享技術知識  → Technology Review（12-20 頁）
報告進度      → Project Update（8-12 頁）
說明問題      → Problem Analysis（10-15 頁）
教學操作      → Training Material（20-30 頁）
```

| 類型 | 對象 | 時間 | 重點 |
|------|------|------|------|
| Equipment Proposal | 主管 + 技術 | 20-30 min | ROI、技術能力 |
| Technology Review | 技術團隊 | 30-45 min | 技術細節 |
| Project Update | 利害關係人 | 15-20 min | 進度、問題、時程 |
| Problem Analysis | 混合 | 20-30 min | 根因、解法 |

## Equipment Proposal 結構

### 10-15 頁建議流程

| 頁數 | 內容 | 重點 |
|------|------|------|
| 1 | 標題頁 | 設備名、報告人、日期 |
| 2 | Executive Summary | What/Why/Benefit/Ask（一頁講完）|
| 3 | 現況與問題 | 痛點量化（時間、品質、成本）|
| 4 | 解決方案概述 | 系統圖、關鍵差異 |
| 5 | 技術規格 | 比較表（現況 vs 提案）|
| 6 | 運作流程 | 4-6 步驟流程圖 |
| 7 | 關鍵技術 | 3-4 個技術亮點 |
| 8 | 效益分析 | 營運/品質/成本效益 |
| 9 | 實施計畫 | 時程表、里程碑 |
| 10 | 成本與 ROI | 投資金額、回收期 |
| 11 | 風險評估 | 風險/機率/因應 |
| 12 | 替代方案 | 比較表、為何選此方案 |
| 13 | 下一步 | 具體行動項目、決策請求 |
| 14 | Q&A | 聯絡資訊、備用投影片清單 |

### Executive Summary 範例

```
PD20 自動化檢測系統
- 減少 FOUP 門板檢測時間 60%
- 檢測準確率 85% → 99%
- 投資：$450K｜回收：14 個月
```

## Project Update 結構

### 8-12 頁建議流程

| 頁數 | 內容 |
|------|------|
| 1 | 標題頁 |
| 2 | 執行摘要（狀態燈號：🟢🟡🔴）|
| 3 | 本期完成項目 |
| 4 | 進行中項目 |
| 5 | 問題與風險 |
| 6 | 時程狀態（甘特圖）|
| 7 | 下期計畫 |
| 8 | 需要支援事項 |

### 狀態燈號定義

```
🟢 綠燈：按計畫進行
🟡 黃燈：有風險，需關注
🔴 紅燈：偏離計畫，需介入
```

## 設計原則

### 6-6 法則

```
每頁最多：
- 6 個項目符號
- 每個項目 6 個字
- 總共 6 行文字

例外：數據表格、流程圖可較密集
```

### 視覺層級

```
標題      36pt 粗體
副標題    24pt
內文      18-20pt
註解      12-14pt
```

### 配色建議

```
主色：深藍 #003366（標題）
底色：淺灰 #F5F5F5（背景）
強調：橘色 #FF6600（重點）
正向：綠色 #00AA00
警告：黃色 #FFAA00
負向：紅色 #CC0000
```

## 常見錯誤

### ❌ 內容
- 文字太多（整段貼上）
- 沒有明確結論或行動
- 數據沒有解讀
- 術語沒有說明

### ❌ 設計
- 字體不一致
- 對比度不足
- 圖表沒標籤
- 動畫太花俏

### ❌ 報告
- 背對觀眾唸投影片
- 超時
- 沒準備 Q&A
